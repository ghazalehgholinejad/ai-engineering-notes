# کارگاه کوچک مقایسهٔ بردارها

در این تمرین سه رکورد ساختگی را از سه زاویه می‌بینیم: محاسبهٔ Python، جدول PostgreSQL و collection در Qdrant. بردارها **با دست انتخاب شده‌اند** تا جواب ریاضی ساده باشد؛ خروجی مدل embedding نیستند و معنای متن فارسی را اندازه نمی‌گیرند.

## دادهٔ مشترک

| شناسه | زبان | بردار |
| --- | --- | --- |
| 1 | fa | `[1, 0, 0]` |
| 2 | fa | `[0.8, 0.6, 0]` |
| 3 | en | `[0, 1, 0]` |

سؤال عددی ما بردار `[1, 0, 0]` است. فقط رکوردهای `fa` را می‌خواهیم. به‌لحاظ ریاضی، cosine similarity رکورد اول ۱ و رکورد دوم ۰٫۸ است. Cosine distance متناظر ۰ و ۰٫۲ می‌شود. رکورد سوم به‌دلیل فیلتر زبان از پاسخ کنار می‌رود.

این فیلتر زبان صرفاً شرط آموزشی است و نقش مجوز کاربر را بازی نمی‌کند.

## مرحلهٔ اول محاسبهٔ بدون دیتابیس

از ریشهٔ مخزن:

```bash
python3 examples/vectors/cosine_demo.py
```

خروجی واقعیِ اجرای این تمرین هنگام آماده‌سازی جزوه:

```json
[
  {"id": 1, "similarity": 1.0},
  {"id": 2, "similarity": 0.8}
]
```

کد ابتدا زبان را فیلتر می‌کند، سپس شباهت را می‌سنجد و مرتب می‌کند. این ترتیب برای فهم مسئله انتخاب شده و نشان‌دهندهٔ نحوهٔ اجرای داخلی همهٔ دیتابیس‌ها نیست. تابع آموزشی برای بردارهای کوچک است؛ کتابخانهٔ محاسبات عددی عمومی یا پیاده‌سازی ANN نیست.

**خودت تغییر بده:** فیلتر زبان را بردار و ترتیب سه رکورد را حدس بزن. سپس بردار اول را به `[2,0,0]` تغییر بده؛ چرا شباهت کسینوسی آن با query همچنان ۱ می‌ماند؟

## مرحلهٔ دوم همان ایده با pgvector

فایل [pgvector_demo.sql](../../examples/vectors/pgvector_demo.sql) برای خواندن و اجرای اختیاری در یک دیتابیس آزمایشی است. پیش‌نیاز: PostgreSQL، نصب افزونهٔ pgvector روی سرور، مجوز فعال‌سازی آن و ابزار `psql`.

```bash
psql --dbname=your_disposable_database --file=examples/vectors/pgvector_demo.sql
```

در فایل، جدول موقت `vector(3)` دارد. عملگر `<=>` فاصلهٔ کسینوسی را می‌دهد؛ ترتیب صعودی، فاصلهٔ کمتر را جلو می‌آورد. انتهای فایل `ROLLBACK` است تا تغییرات تراکنش باقی نمانند. این مثال بدون ایندکس تقریبی است؛ خط HNSW صرفاً کامنت آموزشی برای دادهٔ بزرگ‌تر است. [مرجع pgvector](https://github.com/pgvector/pgvector)

**وضعیت بررسی:** SQL در این نوبت روی PostgreSQL اجرا نشده است. اعداد ذکرشده انتظار ریاضی‌اند؛ عدد اعشاری واقعی ممکن است اختلاف گردکردن داشته باشد.

## مرحلهٔ سوم همان ایده با Qdrant

پیش‌نیاز: یک Qdrant آزمایشی محلی با API در `http://127.0.0.1:6333`. روش راه‌اندازی را از [راهنمای رسمی](https://qdrant.tech/documentation/quickstart/) بخوان. فرمان‌های زیر سرور را نصب یا اجرا نمی‌کنند و برای سرویس احراز هویت‌شده باید تنظیمات همان سرویس را اضافه کنی.

ابتدا collection جدید بساز؛ نام `learning_notes_vectors_demo` نباید از قبل وجود داشته باشد. اگر این مرحله خطا داد، ادامه نده؛ فایل points عمل upsert انجام می‌دهد و روی شناسهٔ موجود می‌تواند داده را جایگزین کند.

```bash
curl --fail-with-body -X PUT \
  http://127.0.0.1:6333/collections/learning_notes_vectors_demo \
  -H 'Content-Type: application/json' \
  --data-binary @examples/vectors/qdrant_collection.json
```

پس از موفقیت ساخت، سه point آزمایشی را وارد کن:

```bash
curl --fail-with-body -X PUT \
  'http://127.0.0.1:6333/collections/learning_notes_vectors_demo/points?wait=true' \
  -H 'Content-Type: application/json' \
  --data-binary @examples/vectors/qdrant_points.json
```

و query را بفرست:

```bash
curl --fail-with-body -X POST \
  http://127.0.0.1:6333/collections/learning_notes_vectors_demo/points/query \
  -H 'Content-Type: application/json' \
  --data-binary @examples/vectors/qdrant_query.json
```

در فایل query، `exact: true` برای مثال دقیق کوچک انتخاب شده است. انتظار داریم شناسه‌های ۱ و ۲ به‌ترتیب، با score کسینوسی نزدیک ۱ و ۰٫۸ برگردند. آن را با ستون **distance** مثال SQL اشتباه نگیر. این دادهٔ سه‌ردیفی برای سنجش سرعت، ANN یا اثر ایندکس payload مناسب نیست. [مرجع Query API](https://api.qdrant.tech/api-reference/search/query-points)

**وضعیت بررسی:** ساختار فایل‌های JSON بررسی شده، اما فرمان‌ها در این نوبت علیه Qdrant اجرا نشده‌اند. collection پس از اجرا روی سرور آزمایشی باقی می‌ماند؛ این جزوه فرمان حذف خودکار ندارد.

## چیزی که باید از مثال بماند

شکل ذخیره و API متفاوت است، اما مسئلهٔ آموزشی یکسان است: بردار سازگار، معیار مشخص، فیلتر و محدودیت تعداد نتیجه. در پروژهٔ واقعی باید مدل embedding، دادهٔ متن و ارزیابی ارتباط را به این مسیر اضافه کنی؛ بردارهای دستی فقط برای فهم مکانیک هستند.
